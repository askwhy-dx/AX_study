# advance 2step 강사 시연 — 서브 vs 팀, 주고받기를 보여 준다

목적: 교육생이 **누가 누구에게 말하는지**를 화면으로 본다.
- 서브: 담당끼리 서로 말할 수 없다 → **메인이 받아서 옮긴다** → 화면에 `[전달]` 줄.
- 팀: 담당끼리 **직접** 쪽지를 보낸다 → 메인은 사본만 받는다 → 화면에 `[참관]` 줄.

시연 폴더 = `AX_study\advance\2step\adv2_demo\cs_practice` (여기서 claude 가 켜진다). 에이전트 `cs-reply` 는 그 위 `adv2_demo\.claude\agents\`. 팀 기능은 이 폴더의 `.claude\settings.local.json` 에 늘 켜져 있다.
현재 폴더가 `adv2_demo\cs_practice` 가 아니면 「시연 폴더에서 켜 주세요 — 바탕화면 advance_2step_시연 bat」이라고 말하고 멈춘다.

## 인자 (bat 이 넘긴다)
- `sub` → 0 · 1 만 하고 끝낸다.
- `team` → 0 → 2 → `답변\주고받기_서브.md` 가 남아 있으면 3(서브 횟수는 그 파일에서 센다).
- 인자 없음 → 0 → 1 → 「팀 시연으로 넘어가려면 **다음** 이라고 해 주세요」 → 2 → 3.

**파일 쓰기 · 고치기는 Write · Edit 도구로만 한다**(메인 · 서브 · 팀원 모두). python · node · PowerShell 로 파일을 고치지 않는다 — 시연 중 허락 창이 뜬다. 서브 · 팀원을 부를 때 프롬프트에 이 한 줄을 넣는다.

설명은 짧게 — 강사가 말로 덧붙인다. 각 시연 시작 전에 「지금 볼 것」 2줄을 먼저 출력한다.

## 0. 준비
1. **처음 상태로**: 명령 하나만 실행한다 — `node ../reset.js <인자>`(인자 없으면 `sub`). `답변\` 파일을 `..\_지난시연\<시각>\` 으로 옮긴다(지우지 않음). `team` 이면 `주고받기_서브.md` 는 사본만 보관하고 제자리에 남긴다(끝의 비교표용). 다른 명령(Move-Item · mv · PowerShell 스크립트)으로 대신하지 않는다 — 허락 창이 뜬다. `문의.txt` · `응대규정.md` · `응대규정_옛판.md` 는 건드리지 않는다.
2. 기록 목록 `LOG` 를 비운 채 시작한다. 아래에서 `[전달]` · `[참관]` 줄을 출력할 때마다 같은 줄을 `LOG` 에도 넣는다.

## 1. 서브 시연 — 메인이 옮긴다
1. 출력:
   > **[시연 1] 서브 에이전트** — 응대 담당이 **일부러 옛 규정**으로 쓰고, 검산 담당이 찾고, 응대 담당이 고칩니다.
   > 볼 것: 검산 담당은 응대 담당에게 **직접 말할 수 없습니다.** 제가 받아서 옮길 때마다 **[전달]** 줄이 찍힙니다. 아래 에이전트 패널에서 ↑↓ · Enter 로 각자 화면도 볼 수 있습니다.
2. 아래 순서대로 한다. **에이전트를 부르기 직전과 결과를 받은 직후에 반드시 `[전달]` 줄을 한 줄씩 출력한다**(형식 `[전달] 보낸 쪽 → 받는 쪽 : 한 줄 요약`). 첫 `Agent` 호출과 같은 메시지 안에, 호출보다 **앞에** 위 「[시연 1]」 안내 2줄과 첫 `[전달]` 줄을 글로 먼저 쓴다(11-07 실측: 안내 · 첫 줄 없이 바로 불러 화면에 안 찍힘).
   1. `[전달] 메인 → cs-reply : 응대규정_옛판.md 로 문의 15건 답변을 써 줘` → `cs-reply` 서브를 부른다. 이번에는 응대규정_옛판.md 를 보고 쓰라고 한다(시험).
   2. 결과를 받으면 `[전달] cs-reply → 메인 : <저장한 파일 이름> 저장 · <결론 한 줄>`.
   3. `[전달] 메인 → 검산 : <파일 이름> 을 응대규정.md 와 문의마다 대조해 줘` → `general-purpose` 서브를 검산 담당으로 부른다(에이전트 파일은 만들지 않는다). 검산은 답변 파일을 응대규정.md(현행)와 대조해 **규정과 다른 문의 번호와 이유만** 돌려준다. 답변은 고치지 않고, 말투 차이는 세지 않는다.
   4. `[전달] 검산 → 메인 : 문의 <번호들> 다름 — <이유 짧게>` (모두 맞으면 `일치`).
   5. 다르면 `[전달] 메인 → cs-reply : 문의 <번호들> 을 현행 규정으로 고쳐 줘 — <검산의 이유 그대로>` → `cs-reply` 를 다시 불러 현행 규정으로 고친 답변 파일을 새로 만들게 한다(덮어쓰지 않는다 = `_v2`).
   6. `[전달] cs-reply → 메인 : <고친 파일 이름> 저장`.
3. 끝나면 출력:
   - `검산: 고침 — 문의 <번호들>` 한 줄, 고친 문의마다 「문의 N: 처음 답 → 고친 답」 한 줄.
   - **대화 기록 (서브)** 제목 아래 `LOG` 의 `[전달]` 줄을 순서대로 다시 모아 보여 준다.
   - 「검산 담당과 응대 담당은 서로 한마디도 직접 하지 않았습니다. 제가 옮긴 횟수: <메인 → 으로 시작하는 줄 수>」
4. `LOG` 의 서브 줄을 `답변\주고받기_서브.md` 로 저장한다(맨 위 제목 `# 서브 — 메인이 옮긴 기록`).
4-1. **처리 결과(교육생이 볼 결과물)** — `문의.txt` · 처음 답변 파일 · 고친 답변 파일을 읽고 `답변\처리결과_서브.md` 를 Write 로 쓴다. 화면에도 「한눈에」 표와 「검산이 없었다면」을 그대로 출력한다.
   - `## 한눈에`: 처리 | 건수 | 문의 — 요청 수락 · 규정상 불가 안내 · 담당자 확인 · 연결 · 그 밖 · **검산이 바로잡음**(굵게).
   - `## 문의별 처리`: 문의 | 학부모 요청(한 구절) | 처리(최종 답의 결론 한 구절 · 근거 규정 수치) | 검산(바뀐 문의만 「처음: … → 고침」).
   - `## 검산이 없었다면`: 바로잡은 문의마다 학부모가 어떤 불이익을 받았을지 한 줄 + 「작성과 검산을 다른 담당에게 맡겨서 잡았다」. ⚠️ 「쓴 담당은 자기 답을 다시 봐도 못 찾는다」고 쓰지 않는다 — 11-07 실측에서 싱글이 스스로 현행 규정과 대조하면 3/3 회 모두 찾았다.
   - 바로잡은 문의 번호는 검산이 실제로 찾은 것만 쓴다(미리 아는 정답을 쓰지 않는다).
5. 인자가 `sub` 면 「서브 시연 끝」하고 멈춘다. 인자가 없으면 「팀 시연으로 넘어가려면 **다음** 이라고 해 주세요」하고 멈춘다.

## 2. 팀 시연 — 담당끼리 직접 (「다음」 또는 인자 `team`)
1. 출력:
   > **[시연 2] 에이전트 팀** — replier(응대) · policy(규정) · parent(학부모 관점) 3명. replier 는 **일부러 옛 규정**으로 씁니다.
   > 볼 것: 담당끼리 보내는 쪽지가 **[참관]** 줄로 찍힙니다. 저는 보기만 하고 아무것도 옮기지 않습니다. 아래 패널에서 ↑↓ · Enter 로 팀원 화면을 볼 수 있습니다.
2. **팀원 3명을 이름을 붙여 한 메시지에서 동시에 띄운다(백그라운드).** 이 버전은 `TeamCreate` 가 없다 — `Agent` 에 `name` 을 주면 팀원이 되고, 팀원끼리 `SendMessage({to: "<이름>"})` 로 직접 말한다.
   `Agent` 에 `name` 파라미터가 없거나 `SendMessage` 가 없으면 「팀 기능이 꺼져 있습니다 — exit 후 이 폴더에서 claude 를 다시 켜 주세요」라고 말하고 멈춘다. 이름 없는 서브로 흉내 내지 않는다.
   - `replier` (subagent_type `cs-reply`): 처음에는 응대규정_옛판.md 를 보고 문의.txt 15건 답변을 써서 `답변\팀.md` 로 저장한다(이 시연에서는 같은 이름 덮어쓰기 허용). 다 쓰면 `policy` 와 `parent` 에게 알린다. 고치라는 말을 받으면 그대로 고쳐 저장하고 다시 알린다.
   - `policy` (subagent_type `general-purpose`): `답변\팀.md` 를 응대규정.md(현행)와 문의마다 대조한다. 다르면 **replier 에게 직접** 문의 번호와 이유를 보낸다. 말투는 보지 않는다. 모두 맞으면 `SendMessage({to: "main"})` 로 최종 결과를 준다: 처음 다른 문의 · 이유 · 고친 뒤 일치 여부.
   - `parent` (subagent_type `general-purpose`): 학부모가 읽는다고 생각하고 알아듣기 쉬운지 · 차갑지 않은지 본다. 고칠 문장을 **replier 에게 직접** 제안한다(한 번에 최대 3개). 규정 내용은 바꾸라고 하지 않는다.
   - 각자의 프롬프트에 넣는다: 이 폴더 절대경로 · 파일 위치 · 자기 할 일 · 「파일은 Write · Edit 도구로만(python · 셸 금지)」 · **다른 두 팀원의 이름과 할 일** · 「내 출력 글은 다른 팀원에게 안 보인다. 말은 반드시 SendMessage 로」 · 「메인에게 최종 보고는 policy 만 한다」 · **참관 사본 규칙**: 다른 팀원에게 `SendMessage` 를 보낼 때마다 바로 이어서 `main` 에게도 `[참관] <내 이름> → <받는 이름> : <보낸 내용 한 줄 요약>` 을 보낸다. 사본은 기록용이라 메인의 답을 기다리지 않는다.
3. 팀원이 일하는 동안 메인은 **아무것도 전달하지 않는다**(팀원에게 SendMessage 를 쓰지 않는다). `[참관]` 사본이 오면 **받은 줄 그대로 한 줄만** 출력하고 `LOG` 에 넣는다 — 덧붙이는 말 · 답장 · 전달 없이. `policy` 의 최종 보고를 기다린다.
4. 끝나면 출력:
   - 문의 <번호들>: 처음 답 → 고친 답 (한 줄씩) · parent 가 바꾼 말투 1~2개
   - **대화 기록 (팀)** 제목 아래 `LOG` 의 `[참관]` 줄을 순서대로 다시 모아 보여 준다.
   - 「틀린 곳을 찾은 사람: policy · 제가 중간에 옮긴 횟수: 0 (사본은 받기만 했습니다)」
5. 서브 4-1 과 같은 형식으로 `답변\처리결과_팀.md` 를 쓴다(「검산」 열 = policy 가 바로잡은 것 · parent 말투 제안은 `## 말투 다듬음` 한 줄씩).
6. `LOG` 의 팀 줄을 `답변\주고받기_팀.md` 로 저장한다(맨 위 제목 `# 팀 — 담당끼리 직접 주고받은 기록`). 아직 돌고 있는 팀원이 있으면 `TaskStop` 으로 멈춘다.

## 3. 나란히 비교 (서브 · 팀 둘 다 한 뒤 · 또는 `답변\주고받기_서브.md` 가 이미 있을 때)
표 하나로 보여 준다.

| | 서브 | 팀 |
|---|---|---|
| 말이 가는 길 | 담당 → 메인 → 담당 | 담당 → 담당 |
| 메인이 옮긴 횟수 | (서브 기록에서 센 수) | 0 |
| 기록 파일 | `답변\주고받기_서브.md` | `답변\주고받기_팀.md` |

마지막 한 줄: 「서브는 제가 옮기고, 팀은 담당끼리 주고받습니다.」

## 하지 않는 것
- 문의.txt · 응대규정 두 파일을 고치지 않는다. `adv2_demo` 밖의 파일을 읽거나 고치지 않는다.
- 정답(문의 4 · 9 · 13)을 미리 말하지 않는다 — 번호는 검산 · policy 가 찾은 것만 보여 준다.
- `[전달]` · `[참관]` 줄을 지어내지 않는다. 실제로 부른 것 · 실제로 받은 사본만 찍는다.
