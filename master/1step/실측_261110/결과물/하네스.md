# cs_practice 하네스 설계표

| 층 | 무엇 | 파일 위치 | 틀리면 |
|---|---|---|---|
| 규칙 | ① 답변마다 맨 끝에 「— 가상 수학교실 상담실 드림」 한 줄 ② 서명 줄은 5줄 제한에 넣지 않음 ③ 직접 쓰든 cs-reply 에 맡기든 서명 줄 확인 ④ 규정 새 판에 이 줄이 빠지지 않았는지 확인 ⑤ 문의 답변은 이 문서의 실행 순서대로 | `CLAUDE.md` | 서명 없는 답변이 나가거나, 서명 줄까지 세어 5줄 제한을 잘못 지킴. 검산 단계를 건너뜀 |
| 기억 | 지금 남아 있는 기억 없음 (`MEMORY.md` 가 비어 있음) | `~/.claude/projects/…cs-practice/memory/MEMORY.md` | 해당 없음. 이 폴더에서 지킬 규칙은 기억이 아니라 `CLAUDE.md` 에 둔다 |
| 훅 | 원본 보호: `문의.txt` · `응대규정.md` · `응대규정_옛판.md` 를 고치거나 지우려 하면 막음 (파일 이름만 보므로 `담당별/응대규정.md` 도 막힘) | `.claude/settings.json` → `.claude/hooks/protect.js` | 원본이 덮어써져 검산 기준이 사라짐 → 막히면 답변은 `답변/` 폴더에 새 파일로 쓴다 |
| 훅 | 비밀정보 검사: `git commit` 전에 `.env` · 슬랙 웹훅 · API 키 · GitHub 토큰 · AWS 키 모양 문자열이 있으면 막음 | `.claude/settings.json` → `.claude/hooks/secret_check.js` | 열쇠가 저장소에 올라감 → 막히면 그 파일을 커밋에서 빼고 `.gitignore` 에 넣는다 |
| 검산 | 답변을 쓴 뒤 에이전트를 하나 더 검산 담당으로 따로 불러, 답변을 `응대규정.md` 와 문의마다 대조 (첫 줄 인사 · 5줄 · 규정에 없는 약속 · 각 조항 숫자 · 서명 줄) | 기준: `응대규정.md` + `CLAUDE.md` 서명 규칙 / 대상: `문의.txt` · `답변/` | 규정과 다른 답변이 나감 → 다르면 cs-reply 가 고치고 한 번 더 대조 |

## 실행 순서
① cs-reply 로 `문의.txt` 의 문의마다 답변을 쓴다.
② 검산 담당 에이전트를 따로 불러 답변을 `응대규정.md` 와 문의마다 대조한다.
③ 다르면 cs-reply 가 고치고, 검산 담당이 한 번 더 대조한다.
④ 결과를 3줄로 보고한다: 검산 결과 · 파일 이름 · 고친 문의.
