## ① 데이터 전처리 — 숫자를 세기 전에 자료를 다듬는 일

**한 줄 요약**: 회사 시스템에서 뽑은 원자료는 그대로 세면 숫자가 틀리므로, 5개 담당(에이전트)이 순서대로 이어받아 "믿고 셀 수 있는 표"로 다듬는다.

**왜 필요한가 (비전문가용 설명)**
- 같은 사람이 여러 번 신청해 **중복**으로 들어가 있다
- 어느 광고를 보고 왔는지 **빈칸**인 건이 있다
- **학년 표기가 제각각**이다

**매일 아침 자동으로 도는 5단계**

| # | 단계 | 주체 | 내용 |
|---|---|---|---|
| 1 | 자료 모으기 | 자동 | 사업부(직영·FC·키즈)별 신청·응시·등록 자료를 내려받아 한 파일에 모음 |
| 2 | 빈칸 찾아 목록 만들기 | 자동 | 온라인 유입인데 광고 출처가 빈 건을 골라 담당자용 빈 양식 생성. **이미 채운 것은 제외**, 새로 생긴 것만 |
| 3 | 담당자가 광고 이름 채움 | **사람 (유일한 수작업)** | 개별 건이 아니라 **광고 종류 단위**로 1회. 목록 0건 = 그날 할 일 없음 |
| 4 | 채운 내용을 되돌려 넣기 | 자동 | 같은 조건의 모든 건에 일괄 반영. 지금까지 채운 파일을 **누적**해 쓰므로 과거분이 사라지지 않음 |
| 5 | 중복 정리·표기 통일·연결 | 자동 | 반복 신청을 1건으로 병합(앞뒤 공백까지 동일인 인식), 학년 표준화, 각 신청이 **응시했는지·등록했는지** 표시 |

**성과 메시지 3종**
- 담당자 손이 닿는 곳 = **5단계 중 1곳**
- 반복 요청 **매일 → 0건** (새로 생긴 것만 요청)
- 집계 기준은 **한 곳에서만** 관리 → 사람마다 다른 기준으로 세는 일 없음

## ② 데이터 검증 — 틀린 숫자가 나가지 않게 막는 일

**한 줄 요약**: 대시보드는 사람 없이 매일 아침 자동 발행되므로, 발행 직전 5단계 검사를 통과한 화면만 내보낸다. 하나라도 걸리면 **새 화면을 내보내지 않고 어제 화면을 유지**한다.

**발행 전 통과해야 하는 5단계**

| 단계 | 검사 | 주체 | 내용 |
|---|---|---|---|
| 1 | 원자료 | 기계 | 건수 0 / 빈값·음수 / 미등록 센터 혼입 여부 |
| 2 | 계산 | 기계 | 가공된 표를 거꾸로 재합산해 원본 합계와 **오차 0** 대조 |
| 3 | 화면 | 기계 | 로봇이 실제 대시보드를 열어 화면 숫자를 읽어 원본과 대조 |
| 4 | 동작 | **AI** | AI가 사람처럼 필터를 바꾸고 카드를 펼치고 그래프에 올려봄 — **14개 항목** 점검 |
| 5 | 종합 | 판정 | 1~4 중 중대 문제 하나라도 있으면 발행 차단 |

**검사에 걸렸을 때 (사람을 부르기 전 자가복구)**

```
AI가 원인 진단 → 스스로 수정(딱 1회) → 처음부터 재검사
  → 통과하면 발행 / 그래도 실패하면 되돌리고 담당자 호출
```

- AI가 고칠 수 있는 범위를 **화면 생성 파일 2개로만 제한** → 원본 자료·집계 기준은 건드릴 수 없음
- 모든 수정 시도는 기록으로 남아 사후 검토 가능

**성과 메시지 3종**
- 잘못된 발행 = **구조적으로 차단** (통과 못 하면 화면이 안 바뀜)
- 알림은 **필요할 때만** (정상이면 침묵)
- 검사기가 헛발질한 사례를 쌓아 **2번 반복되면 다음부터 회피** (자가 학습)

### 1쪽 — 사내 AI 에이전트 업무 지형도 : 시키는 일에서 맡기는 일로
*(From Prompt to Harness)*

> 여름 이벤트 성과 집계와 와이즈만 FC 대시보드 — **AI가 실제로 판단·수행하는 업무**만 4단계로 정리했다

| | 1단계 프롬프트 엔지니어링 | 2단계 컨텍스트 엔지니어링 | 3단계 에이전틱 AI | 4단계 하네스 엔지니어링 **(현재)** |
|---|---|---|---|---|
| **AI가<br>하는 일** | **잘 시키기**<br>무엇을 어떤 기준으로 할지 한 번에 정확히 지시한다 | **보여줄 것을 고르기**<br>판단 근거가 되는 자료를 한 곳으로 모아 고정한다 | **스스로 하기**<br>계획을 세우고 도구를 써서 검사·진단·수정까지 수행한다 | **못 하게 막기**<br>건드릴 수 있는 범위·횟수·되돌림을 설계해 자율에 울타리를 친다<br>〔배지〕 **지금 우리가 있는 자리** |

**우측 패널 — 핵심 전환: 무엇을 시킬까에서 무엇을 못 하게 할까로**
`잘 시키는 기술` ➜ `안전하게 맡기는 설계`
AI를 얼마나 똑똑하게 쓰느냐보다 **어디까지 손대게 하느냐**가 지금의 실무 과제다

**하단** — 잘 시키는 기술에서 시작해, 안전하게 맡기는 설계로 — 두 시스템 모두 4단계에 와 있다

### 2쪽 — 프롬프트 엔지니어링 — 한 번에 정확히 시키기
<sub>우상단 라벨: 지시는 사람이 / 판단은 AI가</sub>
AI에게 무엇을, 어떤 기준으로 할지 지시하는 단계. 말로 하지 않고 **문서로 못박아** 매번 같은 답이 나오게 만든다.

**무엇을 하는 단계인가** — 같은 질문에도 AI는 매번 조금씩 다르게 답한다. 그래서 **지시문 자체를 자산으로 관리**한다. 사람이 그때그때 말로 부탁하는 것이 아니라, 판단 기준·금지 사항·보고 형식을 문서에 적어두고 매 실행이 그 문서를 읽게 한다.

| 출처 | 사례 | 내용 |
|---|---|---|
| 여름 이벤트 | 한 문장으로 하루치 업무를 위임 | 스케줄러가 매일 AI를 부른다. `파이프라인 돌리고 백테스트 후 규칙대로 처리해` — "규칙"이 문서에 정의돼 있어 한 문장에 실행·검사·조치까지 담긴다 |
| FC 대시보드 | 검사 지시서를 문서로 고정 | 화면 점검 **14개 항목**과 합격 기준(오차 허용 범위까지)을 문서로 못박았다. 담당자가 바뀌어도, 회차가 달라져도 같은 잣대로 검사된다 |
| 여름 이벤트 | 답변 가드 5조 | 슬랙 봇 지시문에 명문화 — 확정 아닌 수치는 **잠정치임을 반드시 병기**, "등록수"는 세 기준 중 무엇인지 밝히기, 불확실하면 **추측 금지·담당자에게 넘기기** |
| 여름 이벤트 | 담당 범위 밖은 대답하지 않기 | 채널별 전용 지침으로 담당 밖 질문은 도구도 쓰지 말고 정중히 거절하게 했다. 이걸 안 걸면 날씨·잡담까지 답해버린다 |

- **이 단계의 한계** — 지시가 아무리 정교해도, AI가 보는 자료가 여기저기 흩어져 있으면 답이 흔들린다. → **2단계 컨텍스트 엔지니어링**으로
- **사람의 역할** — 판단 기준과 하지 말아야 할 것을 **문장으로 확정**한다. 이 문장이 곧 품질의 상한선이 된다

### 3쪽 — 컨텍스트 엔지니어링 — 무엇을 보고 판단할지 설계
<sub>우상단 라벨: 근거를 좁히면 / 답이 흔들리지 않는다</sub>
지시를 잘하는 것만으로는 부족하다. AI가 **어떤 자료를 근거로 삼을지**를 사람이 미리 정리해 고정하는 단계.

**무엇을 하는 단계인가** — AI에게 자료를 많이 주는 것이 아니라 **정답이 하나로 정해진 자료만** 준다. 같은 숫자를 여러 곳에서 따로 계산하면 어디가 맞는지 아무도 모르게 되므로, 기준이 되는 파일을 하나로 정하고 모두가 그것만 보게 만든다.

| 출처 | 사례 | 내용 |
|---|---|---|
| 여름 이벤트 | 화면·검사기·슬랙봇이 같은 파일 하나만 | 집계가 끝난 결과 파일 하나를 셋이 공유한다. 그래서 **봇의 답과 대시보드 숫자가 어긋날 수 없다.** 봇은 원본 자료나 DB를 아예 보지 않는다 |
| FC 대시보드 | 검사 AI에게 주는 입력은 딱 3개 | 원본 합계 · 가공한 표 · 검사할 화면. 그 외에는 보여주지 않는다. 볼 것이 적을수록 검사 결과가 재현된다 |
| 여름 이벤트 | 기준값을 설정 파일 한 곳으로 | 이벤트 기간 · 광고 번호 · 학년 표기 매핑을 코드 밖 설정 파일로 뺐다. 기준이 바뀌면 **사람이 고칠 곳이 한 군데**다 |
| 여름 이벤트 | 외부 의존 끊어내기 | 학년 매핑을 구글 시트에서 로컬 파일로 옮겼다. **로그인 창이 떠서 무인 실행이 멈추던 문제**가 사라졌다 — 자동화의 실제 걸림돌은 대개 이런 것이다 |

- **이 단계의 한계** — 자료를 잘 차려놔도, 사람이 매번 실행 버튼을 눌러야 한다면 아직 자동화가 아니다. → **3단계 에이전틱 AI**로
- **사람의 역할** — 어느 숫자가 정답인지 **한 곳에서만 관리**한다. 기준이 둘이면 AI도 사람도 답이 갈린다

### 4쪽 — 에이전틱 AI — 스스로 계획하고 실행한다
<sub>우상단 라벨: 사람은 결과만 / 확인한다</sub>
사람이 시킨 한 가지를 대답하는 것이 아니라, **목표를 받아 스스로 방법을 정하고 도구를 써서** 검사·진단·수정까지 해낸다.

**무엇을 하는 단계인가** — AI가 대화 상대가 아니라 **업무 담당자**가 된다. 화면을 직접 열어 눌러보고, 데이터베이스를 조회해 숫자를 재구성하고, 문제를 발견하면 원인을 분류해 조치까지 실행한다. 사람은 그 결과와 근거를 확인한다.

| 출처 | 사례 | 내용 |
|---|---|---|
| FC 대시보드 | 화면을 사람처럼 써보는 검사 | AI가 매 회차 검사 절차를 **스스로 짜서** 필터를 바꾸고 카드를 펼치고 그래프에 올려보며 14개 항목을 점검한 뒤 보고서를 남긴다 |
| 여름 이벤트 | 원천 대조 진단 | AI가 데이터베이스를 직접 조회해 등록 유형을 **독립적으로 재구성**하고 추출본과 대조한다. 불일치는 **4가지 원인**(이력 잘림 / 정형 오류 / 진짜 결함 / 정의 필요)으로 분류한다 |
| 여름 이벤트 | 자가복구 3단 | 검사 실패 시 **진단 → 조치 계획 → 복구 → 재검증**을 스스로 돈다. 최대 3회까지 시도하고, 안 되면 발행을 막고 사람을 부른다 |
| FC 대시보드 | 스스로 고치고 발행 | 진단서를 받아 화면 쪽 문제를 직접 수정하고, **재검사를 통과했을 때만** 발행한다. 실패하면 수정을 되돌린다 |

**실제 사례 —** 설정에 광고 번호가 **5자리로 잘못** 적혀 데이터가 조용히 비었다. AI가 다른 사업부·다른 이벤트의 값을 교차 참조해 올바른 6자리를 추론하고, 설정을 고친 뒤 재추출까지 마쳐 **사람 개입 없이 복구**했다. 반대로 사업 기준 자체가 오염된 경우는 스스로 고치지 않고 **발행을 막고 사람을 호출**했다.

- **이 단계의 한계** — 자율성이 커질수록 **잘못 고칠 위험**도 같이 커진다. 스스로 고칠 수 있다는 것은 스스로 망칠 수도 있다는 뜻이다. → **4단계 하네스 엔지니어링**으로

### 5쪽 — 하네스 엔지니어링 — 자율에 울타리를 친다
<sub>우상단 라벨: 가장 중요한 설계는 / 못 하게 하는 설계</sub>
AI를 더 똑똑하게 만드는 일이 아니라, **손댈 수 있는 범위·횟수·되돌리는 방법**을 미리 설계하는 일. 지금 두 시스템의 실무 과제다.

**무엇을 하는 단계인가** — 사람이 없는 새벽에 AI가 판단하고 고친다. 그래서 **잘 하도록 만드는 것보다 크게 망치지 못하게 만드는 것**이 먼저다. 무엇을 고칠 수 있는지, 몇 번까지 시도할 수 있는지, 실패하면 어떻게 되돌리는지를 코드로 강제한다.

| 분류 | 항목 | 내용 |
|---|---|---|
| 울타리 | 손댈 수 있는 파일만 | 편집 허용 목록을 고정했다. 여름 이벤트는 **설정 파일 1개**, FC 대시보드는 **화면 파일 2개**뿐. 원본 자료와 집계 로직은 AI가 편집할 수 없다 |
| 울타리 | 코드 대신 메뉴에서 고르기 | AI가 조치 코드를 짜지 않는다. **재실행 · 설정 교정 · 사람 호출** 3가지 중 하나만 고르게 하고, 그 선택이 형식 검문을 통과해야 실행된다 |
| 울타리 | 횟수와 시간 상한 | 수정 시도 1회, 복구 3회, 대화 턴수와 실행 시간에도 상한을 뒀다. 무한 반복으로 시간을 태우지 못한다 |
| 되돌림 | 고친 뒤 반드시 재검사 | 수정했다고 바로 나가지 않는다. 처음부터 다시 검사해 통과해야만 발행되고, **실패하면 자동으로 되돌려** 직전 발행본을 유지한다 |
| 금지선 | 넘지 않는 선 | 사업 기준(등록 유형 · 승급 정의)의 자동 변경은 **절대 금지 — 100% 사람 승인**. 광고 이름 채우기도 AI에게 맡기지 않고 사람이 전담한다 |
| 추적 | 나중에 되짚을 수 있게 | 회차별 자료를 동결해 보관하고, AI의 수정 내역과 출력을 영구 기록한다. 알림은 **성공 채널 / 판단 필요 채널**로 나누고 변경이 없으면 침묵한다 |

- **이 설계가 없으면** — AI가 원인을 못 찾을 때 **기준 자체를 고쳐서 통과시켜 버린다.** 검사는 늘 통과하는데 숫자는 틀린 상태가 된다 — 가장 위험한 실패
- **안전한 학습** — 검사기가 헛짚은 사례는 노트에 쌓아 **2번 반복될 때만** 반영한다. **추가만 가능**하고 기존 규칙의 수정·삭제는 사람만, 변경 시 스냅샷과 알림이 함께 남는다

### PPT 변환 (`node ppt.js`) — 2종

| 명령 | 산출 | 성격 |
|---|---|---|
| `node ppt.js` | `AI에이전트_업무_4단계.pptx` | **편집 가능판**(기본). 도형·글자를 네이티브로 다시 쌓음 |
| `node ppt.js image` | `..._이미지판.pptx` | 쪽 전체를 그림 한 장으로. 모양은 원본과 100% 동일하나 편집 불가 |

필요 도구: Node(Playwright) + Python `python-pptx`. `ppt.js`가 캡처·추출 후 `ppt_build.py`를 자동 호출한다.

**편집 가능판이 만들어지는 방식** — HTML에서 좌표·색·서체를 뽑아 PPT 요소로 옮긴다.

| 원본 | PPT |
|---|---|
| `.matrix .cell .case .def .chip .badge .src` 등 박스 | 네이티브 도형(둥근 사각형). 채움·테두리·점선·모서리 반지름 그대로 |
| `.chev` 셰브론 | 네이티브 **PENTAGON**(오각형=화살표) + 그라데이션 채움 |
| 모든 글자 | 네이티브 텍스트 상자. `<b>`=굵게, `<code>`=Consolas, `<br>`=문단 분리로 보존 |
| SVG 아이콘 | 투명 배경 PNG (도형화 불가 — 아이콘은 편집 대상이 아니라 판단) |

### 페이지맞춤 옵션 (2026-07-21 추가)

**① 페이지 크기 프리셋** — 원고는 항상 1920×1080 CSS px로 그리고 `scale`로 축소한다.

| 명령 | 페이지 | 용도 |
|---|---|---|
| `node pdf.js` | **13.333 × 7.5in (960×540pt)** | 기본. PPT 16:9와 동일 규격이라 슬라이드에 그대로 넣힌다 |
| `node pdf.js a4` | A4 가로 (841.9×595.9pt) | 인쇄용. 16:9가 A4보다 납작해 남는 위아래를 **마진으로 줘 세로 중앙**에 온다 |
| `node pdf.js raw` | 1920×1080px (1440×810pt) | 원본 크기. 20인치짜리 큰 페이지라 뷰어가 과하게 축소한다 — 권장하지 않음 |

⚠️ `harness_deck.html`의 `@page`에 **`size:`를 다시 넣으면 프리셋이 무시된다.** `@page{margin:0}`만 둘 것.

**② 열었을 때 한 쪽이 화면에 꽉 차게** — PDF Catalog에 뷰어 지시를 넣는다(증분 업데이트, 원본 바이트는 안 건드림).

| 키 | 효과 |
|---|---|
| `/OpenAction [1쪽 /Fit]` | 열자마자 한 쪽이 창에 맞춰짐 |
| `/PageLayout /SinglePage` | 연속 스크롤이 아니라 **한 번에 한 쪽씩** |
| `/ViewerPreferences <</FitWindow true>>` | 창을 문서 크기에 맞춤 |

끄려면 `node pdf.js slide --noview`.

### ⚠️ PDF 렌더 성능 규약 (2026-07-21 — 쪽 넘김 버벅임 수정)

초판은 쪽을 넘길 때마다 눈에 띄게 버벅였다. 원인은 **디자인용 반투명 효과**였다 —
Chromium이 PDF로 뽑을 때 이것들을 벡터가 아니라 **전면 크기의 알파 래스터 이미지 + 소프트마스크**로 굳혀버려,
뷰어가 쪽마다 1920×1080 이미지를 다시 합성했다. 파일도 1MB였다.

| 제거한 것 | 대체 |
|---|---|
| `.wash` 전면 radial-gradient 3겹 | 제거 (`display:none`) |
| `body`/`.sheet` linear-gradient 배경 | 단색 `#f3f6f4` |
| `box-shadow` 4종(카드·패널) | 제거, 테두리로 대체 |
| `rgba(255,255,255,.5~.85)` 반투명 카드 | 배경 위에 **미리 합성한 불투명 hex** |
| SVG 등고선 `opacity=".2~.3"` 그룹 | opacity 속성 제거 + stroke를 합성색으로 |

결과: **1,014KB → 285KB**, 내장 이미지 `0개` · 소프트마스크 `0개` (`/Subtype /Image`, `/SMask` 카운트로 확인).
남은 것은 셰브론·헤더의 axial shading 18개뿐이라 무시할 수준.

📌 **디자인을 손볼 때 `box-shadow`나 반투명 배경을 다시 넣으면 버벅임이 그대로 재발한다.**
겹쳐 보이는 느낌이 필요하면 투명도 대신 **배경색 위에 합성한 단색**을 계산해서 쓸 것.
검증법: `python -c "d=open('...pdf','rb').read(); print(d.count(b'/SMask'), d.count(b'/Subtype /Image'))"` → 둘 다 0이어야 한다.

### 덱에 쪽 추가하기

`harness_deck.html`에 `.sheet` 블록을 하나 더 넣으면 된다. 쪽은 `.sheet{page-break-after:always}`가 가른다
(**`@page`에 `size:`를 넣어 나누는 게 아니다** — 위 페이지맞춤 프리셋이 무시된다).

⚠️ 지형도 배경의 `<path id="bl">`은 **1쪽 `<defs>`에만 정의**돼 있고 나머지 쪽은 `href="#bl"`로 참조한다.
1쪽을 지우거나 순서를 바꾸면 **나머지 쪽 배경이 전부 사라진다.**
