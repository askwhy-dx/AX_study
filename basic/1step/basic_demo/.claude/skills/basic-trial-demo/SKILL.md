# basic 2step 강사 시연

교육생이 화면으로 **두 가지 차이**를 보게 하는 것이 목적이다.
- 서브: 결과가 **나(메인)에게만** 모인다. 서브끼리는 서로 모른다.
- 팀: 팀원끼리 **직접** 메시지를 주고받는다. 내가 전달하지 않는다.

## 인자 (바탕화면 bat 이 넘긴다)
- `sub` → 0 · 1 만 하고 끝낸다(「다음」 안내 없이 「서브 시연 끝」).
- `team` → 0 의 1번(처음 상태로)만 하고 바로 2 로 간다.
- 인자 없음 → 0 → 1 → 「다음」 → 2.

각 파트 시작 전에 화면에 「지금 볼 것」을 2줄로 먼저 말한다. 설명은 짧게 — 강사가 말로 덧붙인다.

## 0. 준비
1. **처음 상태로 되돌린다**: 폴더 맨 위에서 `.claude` · `.vscode` · `_지난시연` · `직영_실습데이터.csv` · `열사전.txt` · `basic시연_*.bat` 를 뺀 것(`리포트` · 에이전트가 남긴 임시 파일 등)을 전부 `_지난시연/YYYYMMDD_HHMM/` 안으로 옮기고(지우지 않는다) 빈 `리포트` 폴더를 만든다. 탐색기에는 `리포트` 와 bat 2개만 남는다.
2. Node 한 줄로 `직영_실습데이터.csv` 의 202609 행 수가 가장 많은 센터 3곳을 고른다. 파일을 통째로 읽지 않는다.
3. 화면에 출력:
   > **[시연 1] 서브 에이전트** — 아래 에이전트 패널에 3명이 뜹니다. ↑↓ 로 골라 Enter 로 들여다보고 Esc 로 나옵니다.
   > 볼 것: 세 결과가 **모두 나에게만** 돌아온다.

## 1. 서브 시연
- `jig-report` 서브 에이전트 3개를 **한 메시지에서 동시에** 부른다. 한 명당 센터 1곳, 202609 기준, `리포트/센터_1.html` · `센터_2.html` · `센터_3.html` 로 저장. 에이전트 파일은 새로 만들지 않는다.
- 셋이 다 끝나면 각자의 결론을 한 줄씩 모아 보여 주고, 마지막에 한 줄: 「세 명의 결과는 모두 나(메인)에게 왔고, 셋은 서로의 결과를 모릅니다.」
- 세 HTML 을 브라우저로 연다(`start` / `Start-Process`).
- 그리고 멈춘다: 「팀 시연으로 넘어가려면 **다음** 이라고 해 주세요.」

## 2. 팀 시연 (「다음」을 받은 뒤)
1. 화면에 출력:
   > **[시연 2] 에이전트 팀** — 분석 · 제작 · 검토 담당 3명. 분석 담당은 **일부러 틀리게** 셉니다(제외 프로그램을 안 뺌).
   > 볼 것: 팀원끼리 보내는 쪽지가 이 화면에 **[참관]** 줄로 차례로 찍힙니다. 저는 보기만 하고 아무것도 옮기지 않습니다.
2. **팀원 3명을 이름을 붙여 띄운다.** 이 버전(2.1.289~)은 `TeamCreate` 가 없고 세션 전체가 하나의 팀이다 — `Agent` 도구에 `name` 을 주면 팀원이 되고, 팀원끼리 `SendMessage({to: "<이름>"})` 로 직접 말한다. 세 명을 **한 메시지에서 동시에** 띄운다(백그라운드).
   `Agent` 에 `name` 파라미터가 없거나 `SendMessage` 가 없을 때만 「팀 기능이 꺼져 있습니다 — exit 후 이 폴더에서 claude 를 다시 켜 주세요」라고 말하고 멈춘다. 이름 없는 서브로 흉내 내지 않는다.
   - `analyst` 분석 담당 (subagent_type `jig-report`): 202609 과목수 · 학생수를 센다. 처음에는 jig-metrics 스킬을 쓰지 말고, 제외 프로그램 목록(셔틀 · 차량 등)만 빼지 말고 센다. 세는 단위와 휴회 · 반이동 조건은 그대로. 다 세면 숫자를 `SendMessage` 로 `builder` 와 `reviewer` 에게 보낸다. `reviewer` 가 고치라고 하면 그 말대로 다시 세서 둘에게 다시 보낸다.
   - `builder` 제작 담당 (subagent_type `jig-report`): `analyst` 의 메시지로 숫자를 받아 `리포트/팀.html` 을 만든다(이 시연에서는 같은 이름 덮어쓰기 허용). 숫자가 바뀌면 다시 만들고 `reviewer` 에게 「다시 만들었다」고 보낸다.
   - `reviewer` 검토 담당 (subagent_type `general-purpose`): jig-metrics 스킬 기준으로 CSV 에서 다시 센다. `analyst` 의 숫자를 받으면 대조하고, 다르면 **`analyst` 에게 직접** `SendMessage` 로 무엇이 왜 다른지 되돌려 보낸다. 고친 리포트가 나오면 `SendMessage({to: "main"})` 로 최종 결과를 준다: 처음 숫자 · 고친 숫자 · 무엇을 지적했나.
   - 각자의 프롬프트에 넣는다: 이 폴더 절대경로 · 파일 위치 · 자기 할 일 · **다른 두 팀원의 이름과 할 일** · 「내 출력 글은 다른 팀원에게 안 보인다. 말은 반드시 SendMessage 로」 · 「메인에게는 reviewer 만 최종 보고한다」 · **참관 사본 규칙**: 다른 팀원에게 `SendMessage` 를 보낼 때마다 바로 이어서 `main` 에게도 `[참관] <내 이름> → <받는 이름> : <보낸 내용 한 줄 요약>` 을 보낸다. 사본은 기록용이라 메인의 답을 기다리지 않는다.
3. 팀원끼리 일하는 동안 메인은 **아무것도 전달하지 않는다**(SendMessage 를 팀원에게 쓰지 않는다). `[참관]` 사본이 오면 **받은 줄 그대로 한 줄만** 출력한다 — 덧붙이는 말 · 답장 · 전달 없이. `reviewer` 의 최종 보고를 기다린다.
   끝나면 화면에 찍힌 `[참관]` 줄을 「대화 기록」 제목 아래 한 번 더 순서대로 모아 보여 준다.
4. 끝나면 `리포트/팀.html` 을 브라우저로 열고 3줄로 정리한다:
   - 처음 숫자 → 고친 숫자 (과목수 · 학생수)
   - 틀린 곳을 찾은 사람: 검토 담당
   - 내가 중간에 전달한 횟수: 0 (참관 사본은 받기만 했다)
5. 마지막 한 줄: 「서브는 결과가 나에게 모이고, 팀은 팀원끼리 주고받습니다.」 아직 돌고 있는 팀원이 있으면 `TaskStop` 으로 멈춘다.

## 하지 않는 것
- 원본 CSV 를 고치지 않는다. 이 폴더 밖 파일을 읽거나 고치지 않는다.
- 정답 숫자를 미리 말하지 않는다 — 숫자는 에이전트가 센 것만 보여 준다.
